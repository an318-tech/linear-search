# Линейный поиск на Python

Учебный проект: реализация алгоритма линейного поиска, анализ сложности,
эксперименты и график времени выполнения.

## Структура проекта

| Файл | Назначение |
|------|------------|
| `linear_search.py` | Реализация функции `linear_search(lst, target)` |
| `main.py` | Демонстрация: список из 100 случайных чисел и поиск нескольких значений |
| `benchmark.py` | Замер времени для n = 10, 100, 1000, 10000 и построение графика |
| `benchmark.png` | График зависимости времени выполнения от размера списка |

## Запуск

```bash
pip install matplotlib
python main.py        # демонстрация поиска
python benchmark.py   # замеры + график
```

## Алгоритм

Линейный поиск последовательно просматривает элементы списка слева
направо и сравнивает каждый с искомым значением. Как только найдено
совпадение — возвращается индекс; если список закончился — возвращается -1.

```python
def linear_search(lst, target):
    for i, value in enumerate(lst):
        if value == target:
            return i
    return -1
```

## Анализ сложности

**Временная сложность — O(n).**
Каждое сравнение — константная операция, а количество сравнений зависит
от позиции элемента:
- лучший случай: элемент на первой позиции — 1 сравнение, O(1);
- худший случай: элемент в конце или отсутствует — n сравнений, O(n);
- средний случай: в среднем n/2 сравнений, то есть тоже O(n).

**Пространственная сложность — O(1).**
Алгоритму не нужна дополнительная память: только счётчик цикла и
текущий элемент. Сам список — входные данные, они не учитываются.
Это in-place алгоритм.

Вывод: время растёт линейно с размером списка — удвоение списка
удваивает время поиска в худшем случае. Для больших объёмов данных
на отсортированных списках лучше подходит бинарный поиск (O(log n)),
а для частых запросов — хеш-таблицы (O(1) в среднем).

## Результаты эксперимента

Список из 100 случайных чисел (0–999), значения для поиска:
`[913, 654, 44, 71, 999, 1000]`.

| Искомое | Результат |
|---------|-----------|
| 913  | индекс 12 |
| 654  | индекс 0 (первый элемент) |
| 44   | индекс 61 |
| 71   | индекс 81 |
| 999  | не найден (-1) |
| 1000 | не найден (-1) |

Замеры времени (худший случай — элемент не найден, среднее по повторам):

| n | Среднее время | Время на элемент |
|------:|--------------:|-----------------:|
| 10    | 0.65 мкс | 65 нс |
| 100   | 3.36 мкс | 34 нс |
| 1000  | 45.2 мкс | 45 нс |
| 10000 | 487.6 мкс | 49 нс |

Время на один элемент примерно постоянно — это подтверждает
линейную зависимость: рост n в 1000 раз (от 10 до 10000) увеличивает
время примерно в 745 раз, то есть почти пропорционально n.
График `benchmark.png` визуально демонстрирует прямую зависимость.
